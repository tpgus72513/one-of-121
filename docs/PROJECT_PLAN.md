## 5. 3D 캠퍼스 (신규)

### 5-1. Coastal World는 "참고작"이다
- [Coastal World](https://coastalworld.merci-michel.com/)는 Merci-Michel 스튜디오가 **Three.js(WebGL)로 직접 만든 작품**이다.
- 가져다 쓰는 도구나 템플릿이 **아니다.** 분위기(로우폴리, 파스텔 톤, 귀여운 캐릭터, 걸어 다니기)를 **레퍼런스로 삼고**, 같은 계열 기술로 우리가 직접 만든다.

### 5-2. 기술

| 역할 | 기술 | 이유 |
|---|---|---|
| 3D 렌더링 | **React Three Fiber** (Three.js의 React 버전) | Next.js 안에서 컴포넌트로 3D를 만든다. 지금 스택에 그대로 붙음 |
| 편의 기능 | **@react-three/drei** | 카메라, 텍스트 이름표, 모델 불러오기, 모바일 조이스틱 등 기성품 |
| 이동·충돌 | 처음엔 **직접 구현 (키보드/조이스틱 → 위치 이동)** · 필요하면 `@react-three/rapier` | 물리 엔진은 배우는 비용이 큼. 건물 벽 충돌 정도는 간단히 처리 |
| 3D 모델 | Blender 로우폴리 직접 제작 + 무료 CC0 에셋 (Kenney, Quaternius 등) | 캐릭터·나무·벤치는 무료 에셋, 건물은 상자 모양으로 단순화 |
| 모델 파일 | `.glb` (+ Draco 압축) | 웹에서 가장 가볍고 표준적인 3D 형식 |

> Next.js에서는 3D 화면을 `'use client'` + `dynamic(() => import(...), { ssr: false })`로 불러온다. 3D는 브라우저에서만 돌기 때문이다.

### 5-3. 범위를 단계로 나눈다 — 이게 제일 중요

남은 개발 기간은 **약 12일**이다. 3D는 욕심내면 끝이 없어서, 단계를 나누고 **1단계만 11/9 필수**로 잡는다.

| 단계 | 내용 | 마감 |
|---|---|---|
| **1단계 (필수)** | 평평한 땅 + **건물은 색깔 상자 + 이름표** + 캐릭터 이동(키보드·모바일 조이스틱) + 입구 도착 시 버튼 | 11/9 |
| 2단계 (여유 시) | 1차 학과 건물 2개만 실제 모양에 가깝게 모델링, 나무·길·호수 장식 | 11/9 이후 |
| 3단계 (확장) | 다른 사람 캐릭터가 보이는 멀티플레이 (Coastal World처럼) | 공모전 결선용 |

- **실제 캠퍼스 배치**는 네이버/카카오 지도 위성 사진을 보고 건물 위치만 옮겨 온다. 축척은 정확할 필요 없다.
- **학과-건물 연결 정보**는 팀이 직접 확인해서 `departments.json`에 적는다 (아래 7장).
- 고려대 **공식 로고·교표는 쓰지 않는다.** "세종캠 학생이 만든 비공식 프로젝트"로 표기한다. (나중에 학교와 정식으로 하게 되면 그때 허락을 받는다.)

## 6. 1차 학과 미니게임 (⏳ 과별 1개 확정 필요)

> **선택 기준:** ① 웹 개발 공부에 도움이 되는가 ② 사용자가 해봤을 때 재미있는가 ③ **그 과다운가**

### 🔐 인공지능사이버보안학과
v1의 보안 후보 2개를 그대로 가져온다. 과 이름에 "인공지능"이 있으니 **AI 요소를 섞으면** 더 그 과답다.

| 후보 | 방식 | 웹 공부 포인트 | AI 버전 아이디어 |
|---|---|---|---|
| **A. 피싱 문자 판별** | 진짜/피싱 카드를 좌우 스와이프 | 스와이프 제스처, 모바일 대응 | "AI가 만든 피싱 문자"도 섞어서 사람이 쓴 것보다 그럴듯한 피싱을 가려내기 |
| B. 비밀번호 크래킹 | SNS 프로필 단서로 비밀번호 추리 | 해시(SHA-256), 입력 피드백 | — |

**추천: A (피싱 판별).** 모바일에서 손맛이 좋고, 해설로 보안 교육 효과가 있고, "AI 피싱"이 과 이름과 딱 맞는다.
- 상세 설계(단서 종류, JSON 형식, 해설 보여주기, 가상 업체명 사용)는 v1 문서 5장 후보 C 그대로.
- B는 상세 설계가 v1 문서 5장 후보 D에 있다.

### 🧪 식품생명공학과
v1의 "세포 분열"은 생명과학과에 가까워서 **식품생명공학과답게 새로 고른다.**

| 후보 | 방식 | 웹 공부 포인트 | 재미 포인트 |
|---|---|---|---|
| **A. 식중독균 찾기 (현미경)** | 흐린 현미경 초점을 맞추고, 시료 속 식중독균(대장균·살모넬라 등)을 찾아 클릭 | CSS `filter: blur`, 클릭 좌표 판정 | 숨은그림찾기. v1 현미경 후보를 식품 위생으로 바꾼 버전 |
| B. 발효 컨트롤 | 요구르트·김치 발효 중 온도 다이얼을 조절해 유산균 그래프를 목표 구간에 유지 | 실시간 상태 업데이트, 그래프(SVG) | 균형 잡기 게임의 긴장감 |
| C. 위생 점검관 (HACCP) | 식품 공장 그림 속 위생 위반(맨손, 바닥에 둔 원료, 온도 초과 냉장고)을 제한시간 안에 찾기 | 이미지 위 클릭 영역 판정 | 틀린그림찾기, 누구나 바로 이해 |

**추천: A (식중독균 찾기).** v1에서 이미 구현 방식을 정리해둬서 바로 만들 수 있고, 생명(현미경) + 식품(위생)이 한 번에 보인다.
- B는 가장 "공대스러운" 체험이라 재미 검증만 되면 좋은 대안이다.

### 모든 게임 공통 규칙 (그대로)
- 30~60초 안에 끝난다.
- 점수는 **0~100으로 통일**한다.
- `onFinish(점수, 세부기록)` 하나만 호출하는 컴포넌트로 만든다. **3D 캠퍼스와 게임은 서로 코드를 몰라도 된다.**
- 게임 내용(문제·난이도)은 코드 안 JSON, 플레이 결과만 DB.

## 7. 기술 스택 & 구조

### 7-1. 스택

| 역할 | 기술 | 변경 |
|---|---|---|
| 화면 + API | Next.js (App Router) + TypeScript | 유지 |
| 3D 캠퍼스 | React Three Fiber + drei | **추가** |
| 점수·랭킹 DB | Supabase (Postgres) + RLS | 유지 |
| AI 결과 카드 | LLM API (서버 API 라우트에서만 호출) | 유지 |
| 배포 | Vercel + GitHub | 유지 |

API는 그대로 2개: `POST /api/plays` (점수 범위·플레이 시간 검증 후 저장), `POST /api/result-card` (AI 카드 문구 생성).

### 7-2. 폴더 구조

```
src/
├─ app/                            ← 페이지 (폴더 = URL)
│  ├─ page.tsx                     랜딩 + 닉네임/학과 선택
│  ├─ campus/page.tsx              ★ 3D 캠퍼스 (과 선택 화면을 대체)
│  ├─ play/[dept]/page.tsx         학과별 게임 실행
│  ├─ result/page.tsx              점수 + AI 결과 카드 + 공유
│  ├─ ranking/page.tsx             개인 TOP10 + 세종캠 학과별 순위
│  └─ api/
│     ├─ plays/route.ts            점수 검증 + 저장
│     └─ result-card/route.ts      LLM 호출
├─ campus/                         ★ 3D 캠퍼스 전용
│  ├─ Scene.tsx                    땅·조명·카메라
│  ├─ Player.tsx                   캐릭터 이동 (키보드 + 조이스틱)
│  ├─ Building.tsx                 건물 1동 = 상자 + 이름표 + 입구 판정
│  └─ layout.json                  건물 위치·크기 (지도 보고 옮긴 값)
├─ data/
│  └─ departments.json             ★ 세종캠 학과 목록 (학과 ↔ 건물 ↔ 게임)
├─ games/
│  ├─ types.ts                     모든 게임 공통 규칙
│  ├─ registry.ts                  게임 id → 컴포넌트 등록부
│  ├─ phishing/                    인공지능사이버보안학과
│  └─ microscope/                  식품생명공학과
├─ components/                     공통 UI (타이머, 버튼, 결과 카드)
└─ lib/                            Supabase 클라이언트
```

**왜 이렇게 나눴나**
- **`campus/`를 따로 뺐다.** 3D는 배우는 내용이 완전히 달라서, 한 사람이 이 폴더만 맡으면 다른 사람 코드와 부딪히지 않는다.
- **`departments.json` 하나가 학과·건물·게임을 잇는다.** 학과를 추가할 때 이 파일에 한 줄, 게임 등록부에 한 줄이면 끝난다. "모든 과로 확장"이 이 구조 덕분에 가능하다.
- 3D 캠퍼스는 건물에 도착하면 `/play/ai-cybersecurity`로 이동만 한다. 게임은 캠퍼스를 모른다.

```json
// data/departments.json (예시 — 건물·단과대는 팀이 확인해서 채울 것)
[
  { "id": "ai-cybersecurity", "name": "인공지능사이버보안학과", "college": "(확인)", "buildingId": "(확인)", "gameId": "phishing",   "status": "open" },
  { "id": "food-biotech",     "name": "식품생명공학과",         "college": "(확인)", "buildingId": "(확인)", "gameId": "microscope", "status": "open" },
```

- `status: "soon"`인 학과는 3D 캠퍼스에서 회색 건물 + "준비 중" 표시.

## 9. 역할 분담 (3명 · 고루 경험하기)

### 원칙
- **영역별로 나누지 않고, 모두가 세 층을 다 만져본다.** 한 사람이 3D만 하고 다른 사람이 DB만 하면 각자 하나만 배운다.
- 모든 사람이 **① 화면·인터랙션 ② 3D ③ 서버·DB·AI**를 하나씩 맡는다.
- 맡은 건 **폴더 단위**로 나눠서 Git 충돌을 줄인다.

### 분담표

| | ① 화면·인터랙션 | ② 3D 캠퍼스 | ③ 서버·DB·AI |
|---|---|---|---|
| **A 양동규** | 🔐 피싱 판별 게임 (스와이프·모바일 제스처) `games/phishing/` | 캐릭터 이동 — 키보드 + 모바일 조이스틱, 카메라 따라가기 `campus/Player.tsx` | Supabase `plays` 테이블·RLS + **`POST /api/plays`** (점수 검증·저장) |
| **B 추현지** | 🧪 식중독균 찾기 게임 (blur·좌표 판정) `games/microscope/` | 건물 — 상자·이름표·입구 판정·"준비 중" 표시 `campus/Building.tsx`, `layout.json` | **`POST /api/result-card`** — LLM 프롬프트, 실패 시 기본 문구 |
| **C 권세현** | 게임 실행기(타이머·`onFinish`·`registry`) + 랜딩·결과·랭킹 페이지 + 결과 카드 이미지 저장 | 3D 뼈대 — Canvas·땅·조명·Next.js에 3D 불러오기 `campus/Scene.tsx` (+ 11/5 대비 2D 지도 대체안) | 랭킹 SQL (학과별 평균) + `departments.json` 세종캠 학과 목록 + Vercel 배포·환경변수 |

**이렇게 나눈 이유**
- A·B는 게임이 무거운 대신 3D·서버 작업은 한 덩어리씩만 맡는다. C는 게임이 없는 대신 페이지 여러 개와 3D 뼈대를 맡는다.
- **C의 3D 뼈대가 먼저 나와야** A(캐릭터)·B(건물)가 그 위에 얹을 수 있다 → C는 3D 뼈대부터 시작한다.
- 서버 쪽도 셋 다 다른 걸 배운다: A는 **DB·보안(점수 조작 막기)**, B는 **AI API 호출**, C는 **SQL 집계·배포**.
